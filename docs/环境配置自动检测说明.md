# 自动环境检测配置说明

## 功能概述

项目已实现**无感自动环境检测**功能，可以根据运行环境自动加载对应的配置文件：
- **本地开发环境** → 自动加载 `config/.env.dev`
- **云服务器生产环境** → 自动加载 `config/.env.prod`

## 环境检测规则

系统通过以下方式自动判断运行环境（按优先级排序）：

1. **环境变量检测**：检查 `ENV` 环境变量是否为 `production`
2. **主机名检测**：检查主机名是否包含 `server`、`cloud`、`aliyun`、`tencent`、`huawei`、`prod` 等关键词
3. **标识文件检测**：检查是否存在 `/etc/production` 或项目根目录的 `.production` 文件
4. **IP地址检测**：检查主机IP是否为公网IP（非 127.x.x.x、192.168.x.x、10.x.x.x）

## 配置文件说明

### 1. config/.env.dev（开发环境）
```bash
ENV=development
DJANGO_DEBUG=true
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=20060424007Hq265
DB_NAME=supervision
```

### 2. config/.env.prod（生产环境）
```bash
ENV=production
DJANGO_DEBUG=false
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your-production-password
DB_NAME=supervision
```

### 3. config/.env（备用配置）
当 `.env.dev` 或 `.env.prod` 不存在时，会自动加载此文件作为备用配置。

## 使用方法

### 本地开发
直接启动项目，系统会自动检测为开发环境：
```bash
python manage.py runserver
```

输出示例：
```
🌍 Django环境检测: development
📄 加载配置文件: C:\...\config\.env.dev
```

### 云服务器部署
直接启动项目，系统会自动检测为生产环境：
```bash
python manage.py runserver 0.0.0.0:8000
```

输出示例：
```
🌍 Django环境检测: production
📄 加载配置文件: /path/to/config/.env.prod
```

### 手动指定环境（可选）
如果自动检测不准确，可以手动设置环境变量：

**Windows:**
```powershell
$env:ENV="production"
python manage.py runserver
```

**Linux/Mac:**
```bash
export ENV=production
python manage.py runserver
```

### 创建生产环境标识文件（推荐）
在云服务器上创建标识文件，确保始终识别为生产环境：
```bash
# 在项目根目录创建
touch .production

# 或在系统目录创建（需要root权限）
sudo touch /etc/production
```

## 配置文件优先级

1. `config/.env.dev` 或 `config/.env.prod`（根据环境自动选择）
2. `config/.env`（备用配置）
3. 项目根目录 `.env`（向后兼容）

## 安全建议

1. **不要提交敏感配置到Git**
   - `.env.dev` 和 `.env.prod` 已添加到 `.gitignore`
   - 生产环境密码应与开发环境不同

2. **生产环境配置检查清单**
   - [ ] 修改 `DJANGO_SECRET_KEY` 为随机字符串
   - [ ] 设置 `DJANGO_DEBUG=false`
   - [ ] 修改数据库密码
   - [ ] 配置正确的 `ALLOWED_HOSTS`

3. **定期更新密钥**
   - 定期更换数据库密码
   - 定期更换 Django SECRET_KEY
   - 定期更换 API Token

## 验证环境配置

启动项目后，查看控制台输出：
- ✅ 显示 `development` → 开发环境配置正确
- ✅ 显示 `production` → 生产环境配置正确
- ✅ 显示正确的配置文件路径

## 故障排查

### 问题1：环境检测不正确
**解决方案**：手动设置 `ENV` 环境变量或创建 `.production` 标识文件

### 问题2：配置文件未加载
**解决方案**：检查配置文件是否存在于 `config/` 目录，文件名是否正确

### 问题3：数据库连接失败
**解决方案**：
1. 检查MySQL服务是否启动
2. 检查配置文件中的数据库密码是否正确
3. 检查数据库是否已创建：`CREATE DATABASE supervision CHARACTER SET utf8mb4;`
