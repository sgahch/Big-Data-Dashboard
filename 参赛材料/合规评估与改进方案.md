## 四、关键差距详解

### 差距 1：方向偏题——最容易被忽视、却最先卡人（准入）
iCAN 创新赛道只认九大应用领域。本项目是"纪检监察/智慧政务"，不在此列。评委第一反应会是"这不属于我们赛道",后续很难翻。
- **可选解法（三选一，越早定越好）**：
  1. **重构叙事**：把同一套技术讲成"人工智能 + **智慧社区**"——基层小微权力监督/村务公开监测，落到九大领域中的"智慧社区"。改动最小。
  2. **换赛道/换赛事**：改投"互联网+"、"挑战杯"或三创赛，这几类对社会治理/政务类项目友好得多。**这是最省力的路径。**
  3. 并入"智能教育"（廉政教育/党纪学习场景）或"智慧环保"（生态环保监督）——项目库里已有"生态环保"标签，可顺势做大。

### 差距 2：双盲——10 处硬伤，每处 -5 分
经 `demos/clean_double_blind.py` 全量扫描实测，命中院校名 `西安文理学院` 与校域名 `xawl.edu.cn`：

| 文件 | 位置 | 违规形式 |
|---|---|---|
| `index.html` | 第 1477 行 | Logo `<img>` + alt 校名（**主看板首页，正被 urls 直接服务**） |
| `index_fixed.html` | 第 1507 行 | 同上 |
| `login.html` | 第 282 行 | 同上 |
| `config/login.html` | 第 282 行 | 同上 |
| `forgot-password.html` | 第 25 行 | **背景图 `url()` 指向校方服务器** |
| `forgot-password.html` | 第 377 行 | Logo `<img>` + alt 校名 |
| `reset-password.html` | 第 25 行 | **背景图 `url()` 指向校方服务器** |
| `reset-password.html` | 第 365 行 | Logo `<img>` + alt 校名 |
| `docs/可视化平台升级说明.md` | 第 14 行 | 明文"西安文理学院Logo + 校名" |
| `docs/可视化平台升级说明.md` | 第 182 行 | 明文"集成西安文理学院Logo" |

> 两处背景图是被 grep 容易漏掉的隐藏项——**页面会向校方服务器发请求加载图片**，即使替换了 Logo 本身仍会泄露。已由扫描工具捕获。

按规则预估：**10 处 × 5 分 = 50 分净扣分**，且首页作为演示主页面，校名会直接出现在巡展屏幕上。这是**最确定、也最便宜就能挽回的失分点**。

### 差距 3：技术创新性——账面上最贵的一块（60 分）
当前技术栈本质是"工程集成"：抓取靠 requests+BS4，打标靠关键词规则，统计靠 ORM 聚合，AI 靠转发 Coze。任何一个应届生用两周都能复现，评委很难给到"技术突破"。
更要命的是**支撑这些技术的数据是有缺陷的**：
- 案件数据 **100% 无正文** → 宣称的"标题+内容相似度去重""关键词自动识别违规类型"缺乏输入
- **35% 无日期** → 趋势分析、案件查处进军势图的数据不准
- **31% 未打标签** → 违规类型分布图不完整

结果就是：**一个宣称做内容智能分析的系统，其核心数据没有内容。**

> 交叉验证的一个修正：自研分类器在脱敏集上判出 37 条"其他"，与原系统"空标签" 38 条几乎完全重合。人工核对发现这批是政策解读/理论文章（如"明纪释法""理论视野"），**并非案件**。
> 也就是说：所谓"31% 漏标"，主因是**数据混入非案件内容**，而不仅是算法失败。这既是坏消息也是好消息——坏在数据口径不纯，好在算法本身没有大面积误判，**修复方向应改为"案件/非案件前置分类"，而不是一味调打标规则**。

### 差距 4：AI 不能算"自己的"——演示还会塌
`apps/ai_chat/views.py` 的本质是把用户输入 POST 给 `https://api.coze.cn/v3/chat` 再取回。这带来两个问题：
1. **原创性**：核心智能在第三方平台，按 iCAN"强调学生原创"的口径，容易被追问"哪些是你自己做的"。
2. **演示稳定性**：巡展现场网络通常很差，一旦请求失败，界面只返回固定的"AI服务正在配置中"。**评委想看的那一刻，恰好是最可能失败的场景。**

此外 README 宣称的"数据分析解读/自然语言查询/智能报告生成"，代码中只有通用 chat 转发，**并无实现**——这属于"宣称超出实现"，答辩被追问会很被动。

### 差距 5：提交材料缺项 + 内部叙述分裂
- **缺 PPT**（必需件）、缺策划书 Word、缺团队分工表、缺 AI 辅助标识。
- 仓库里同时存在两个系统：`supervision`（看板线，manage.py 默认）与 `lianzhitong`（廉智通业务线：cases/reports/core/users/notifications）。根目录 `设计书.md` 讲的是 Vue3+SpringBoot 的廉智通，README 讲的是 Django+ECharts 的看板——**两份文档指向两个不同产品**。评委问"你们的作品到底是哪个"，很难自圆其说。

### 差距 6：真实具名案件的展示风险
库内存的是真实自然人处分数据（如"韩松严重违纪违法被开除党籍和公职"）。虽然来源是官方公开通报，但在赛场公开屏幕上进行个人维度分析与排名，**强烈建议在演示层做脱敏**（本轮已产出脱敏数据集，见 `demos/data/cases_anonymized.json`，姓名已遮蔽、职务与处置方式保留）。

## 七、风险与禁忌（务必遵守）

1. **不要先做完所有材料再想双盲**——双盲不可逆，从第 1 版起就去除院校/导师/单位信息。
2. **不要编造数据或合作单位**——伪造直接取消资格。没有试用反馈就写"暂无"，不要用虚构单位背书。
3. **不要把 PPT 当策划书交**——策划书是 Word→PDF，两者性质不同。
4. **不要只写 AI 概念**——必须能当场跑起来；网络一断还塌的，等于没有。
5. **AI 辅助内容须标注"AI 辅助制作"**。
6. **不要在演示层展示真实具名案件**——巡展公开屏幕一律使用脱敏数据集（`cases_anonymized.json`，职务与处置方式保留、姓名已遮蔽），避免对真实自然人做公开展示与排名。
7. **谢绝导师课题参赛**——强调学生原创，材料叙事要落在学生自主完成上。
