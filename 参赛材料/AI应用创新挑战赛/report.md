# 一、项目背景

各级纪检监察机关定期对外公开通报违纪违法案件，这些通报覆盖地域广、时间跨度长、问题类型多，本身就是一份高质量的公开监督数据源。但在实践中，这些信息以“给人看的网页”形态存在：基层工作人员要掌握辖区与全区域的监督态势，只能逐站浏览、人工摘录、手工汇总，效率低、易遗漏、难以沉淀为可复用的数据资产。

团队来自高校人工智能与大数据专业方向，在调研基层监督数字化场景时确认了一个核心判断：**公开通报缺的不是信息，而是把信息变成数据、把数据变成判断的工具**。为此，我们把通报从“网页”变成“结构化数据”，构建了一套覆盖数据全生命周期的智能看板系统，并以 AI 算法为核心，实现违规类型自动判定、地区风险热度评估、自然语言查询与案件趋势预测。

本作品即为“AI 监管大数据智能看板”（内部代号：廉智通）。系统已完成端到端贯通：数据可自动采集入库，标签可自动匹配并支持人工修正，看板可多维呈现，报告可一键导出，AI 研判可离线运行，智能问答可在线对话。

# 二、痛点问题

**痛点一：信息分散，获取低效。** 通报分散在各地市的发布渠道，人工逐站浏览、复制、摘录，单轮更新动辄数小时，且极易漏采。

**痛点二：口径不一，汇总困难。** 各地通报的标题结构与行文习惯差异大，同一类问题在不同地区的表述完全不同，人工汇总时口径因人而异，数据难以对齐。

**痛点三：归类依赖个人经验。** “违规插手工程”“生态环保”“教育医疗”等同类问题难以自动归并，完全靠人工判读，经验不可复制、过程不可追溯。

**痛点四：报告产出慢。** 周报、月报、专题汇报需要把数据人工搬进 Word、Excel、PDF，重复劳动量大，格式难统一。

**痛点五：传统看板“只看不问、只看不算”。** 普通可视化平台只能被动展示图表：不能让用户用自然语言直接问数，更不能自动判定问题类型、评估地区风险、预测趋势；而直接接入大模型的方案又强依赖外网，在涉密内网或巡展离线环境下无法运行。

# 三、需求分析

## 3.1 总体需求

系统需要形成完整业务闭环：**自动采集 → 自动治理（去重、打标、人工修正）→ 多维分析 → 可视化呈现 → 报告交付 → AI 辅助研判**。其中 AI 不是点缀，而是贯穿“治理”与“分析”两个环节的核心能力。

## 3.3 非功能性需求

- **离线可用**：自研算法全部本地计算，断网环境可完整演示核心 AI 功能。
- **可解释**：AI 判定必须输出命中证据与得分构成，拒绝“黑盒结论”。
- **可追溯**：全部关键操作写入审计日志，标签修正留痕。
- **易部署**：面向巡展场景支持快速启动演示。

# 六、技术方案

## 6.1 总体架构

@@FIG:arch

- **采集层**：APScheduler 按小时调度，requests + BeautifulSoup 解析列表页，URL 唯一性去重后写入数据库；爬取任务以状态机管理（pending → running → success / failed / stopped），全程记录爬取日志。
- **数据层**：MySQL 8 共 22 张表，核心包括通报主表 news、地区表 region、标签体系 tag / tag_category、监督事项三层关键词表 supervision_item、爬取日志 crawl_log / crawl_task 与审计表 audit_log。模型显式绑定表名，保证与历史库兼容。
- **服务层**：Django + DRF 划分为 news、crawler、stats、users、ai_chat 五个应用，REST 接口统一响应结构。
- **呈现层**：ECharts 多维看板、3D 地区地图，以及 Word / Excel / PDF 报告导出管线。

## 6.2 关键数据设计

| 模型 | 表名 | 设计要点 |
|---|---|---|
| News | news | 通报主表，区分“自动标签”与“手动修正标签”双通道，留存修正人与修正理由 |
| SupervisionItem | supervision_item | 监督事项清单，三层关键词配置（核心词 / 近义词 / 上下文行动词） |
| Tag / TagCategory | tag / tag_category | 二级标签携带关键词用于自动匹配，一级分类带色值 |
| CrawlLog / CrawlTask | crawl_log / crawl_task | 爬取日志与任务状态机 |
| AuditLog | audit_log | 新增、修改、删除、爬取、导出、登录全量审计 |

**设计亮点**：标签双通道解决了“纯规则打标必然有误，但纠错过程不可追溯”的老问题——自动标签保留原始结果，人工修正单独落库并留痕，二者互不覆盖。

## 6.3 AI 技术方案：双轨并行

**轨道一：自研轻量算法（离线、可解释）。** 全部本地计算、零第三方依赖，保证涉密内网与巡展离线场景可用：

1. **违规类型判定**：三层关键词匹配（核心词 / 近义词 / 上下文行动词）后，按“领域关键词权重 + 处置方式权重 + 职务层级权重”三因子加权打分，取得分最高者为判定结果，同时输出每一类的得分与命中证据。
2. **地区风险热度**：热度 = 案件数量（50%）+ 平均严重程度（30%）+ 近年活跃度（20%），归一化后排序。
3. **自然语言查询**：本地意图识别，将“哪个地区最多”“2025 年有多少起”等问句解析为数据聚合动作。
4. **趋势预测**：按年度聚合案件序列，线性回归外推次年规模。

**轨道二：大模型问答代理（在线、智能）。** 服务端封装 Coze v3 chat 接口：统一鉴权、会话轮询取回结果、超时与未配置场景自动降级为友好提示，前端只对接本系统接口，不暴露任何密钥。

# 七、作品功能说明

## 7.1 数据采集与治理

系统按小时自动抓取通报列表页，URL 去重后入库；抓取成功、失败、停止均有日志与任务状态可查。入库后按地区、时间、问题类型三个维度自动归集，关键词自动打标；对打标有误的记录，人工修正单独留痕（修正人、修正理由），原始自动标签不被覆盖。

## 7.2 多维可视化看板

看板按“数据采集、数据处理、数据呈现、数据评估”四个页面组织，支持按地区、时间、问题类型的交叉筛选与下钻，含地区案件分布、类型占比、年度趋势等图表，并配有 3D 地区地图增强空间态势感知。

## 7.3 报告一键导出

统计聚合结果可一键导出 Word（表格 + 段落）、Excel（多 Sheet 分维度）、PDF（注册中文字体）三种格式，直接用于周报、月报与专题汇报。

## 7.4 AI 核心功能（重点）

AI 是本作品区别于普通看板的核心。以下四个自研算法模块全部离线运行、可解释、可复核，均已实测跑通。

@@FIG:aidemo1

**7.4.1 违规类型智能判定。** 输入任意通报文本，系统按三层词表匹配后进行三因子加权打分，输出判定类型与证据链。实测样例“某市委常委、秘书长涉嫌严重违纪违法，目前正接受纪律审查和监察调查”被判定为“执纪审查”，综合得分 64 分，命中证据完整列出：领域关键词、处置方式与职务层级各自得分清晰可查，全过程可解释、可复核。

**7.4.2 地区风险热度评估。** 按案件数量（50%）、平均严重程度（30%）、近年活跃度（20%）三维合成地区热度并排序。实测 8 个地市中渭南市热度 100 分居首，西安市、安康市次之，与案件分布柱状图互相印证。

**7.4.3 自然语言查询（离线 NLQ）。** 本地意图识别引擎支持“哪个地区最多”“2025 年有多少起”“执纪审查多少”“预测明年趋势”等问句，直接返回数据结论；全部计算在本机完成，无需联网。

**7.4.4 趋势预测。** 基于年度案件序列做线性回归外推：实测 2017–2026 年共 123 起、年均约 7.9 起，2023 年达峰 23 起，预测下一年度约 14 起；系统同时明示“样本量较小，预测仅作趋势参考”，不夸大结论。

@@FIG:aidemo2

**7.4.5 AI 智能问答（大模型）。** 在线模式下，用户可就监督数据自由提问，由服务端代理调用大模型生成回答；接口具备完整降级链路（未配置提示、超时提示），保证交互不中断。与离线算法形成互补：离线保证可用与可解释，在线保证开放问答能力。

## 7.5 用户与审计

登录认证、角色区分，新增、修改、删除、爬取、导出、登录全量写入审计日志，满足监督场景对操作留痕的要求。

# 八、使用说明

## 8.1 启动与访问

在项目根目录执行启动命令（默认演示端口 8003），浏览器访问本机地址即可进入系统；数据库连接就绪后，看板与接口即时可用。

@@FIG:opflow

## 8.2 用户操作流程

1. **登录系统**：输入账号密码进入平台。
2. **进入看板**：默认进入总览页，查看地区、时间、类型分布。
3. **多维筛选**：点击导航切换“数据采集、数据处理、数据呈现、数据评估”四个页面，按需筛选下钻。
4. **AI 研判**：在问答窗口自然语言提问；在算法演示页使用违规判定、热度评估、问数与预测。
5. **导出交付**：选择统计维度，一键导出 Word / Excel / PDF。

## 8.3 交互指南

- **看板页**：图表支持悬停查看数值，点击图例可聚焦单类指标。
- **数据管理**：列表支持按地区与标签过滤；对打标有误的记录可进入修正界面，填写修正标签与理由后保存，原始标签自动留痕。
- **AI 问答**：在输入框直接用自然语言提问，回答以对话气泡返回；服务异常时给出友好提示，不中断使用。
- **自研算法演示页**：访问系统内算法演示路径即可离线体验四大 AI 模块——在文本框粘贴通报原文点击“开始判定”查看得分与证据；在问数框输入问题点击“提问”获取结论；热度榜与趋势图自动随数据集生成。

## 8.4 演示建议

巡展或答辩现场建议优先演示**离线 AI 模块**（不依赖网络，稳定可复现），再演示**在线智能问答**（体现开放问答能力），最后演示**报告导出**（体现交付价值）。

# 九、应用前景与商业模式

## 9.1 应用前景

- **横向场景扩展**：本系统的“采集—治理—AI 研判—交付”框架与具体监督业务解耦，可平移到审计、巡察、财政、市场监管等同样依赖公开通报与文书数据的场景。
- **纵向能力深化**：随着正文补抓与数据量增长，判定模型可从规则加权平滑升级为机器学习分类，预测可升级为时序模型；三层词表体系可直接复用为训练标注规范。
- **部署形态灵活**：核心算法离线可用，既支持涉密内网私有化部署，也支持云端多租户服务。

## 9.2 商业模式

| 模式 | 对象 | 内容 |
|---|---|---|
| 私有化部署授权 | 机关与事业单位 | 按部署授权收费，含安装、词表初始化与一年维护 |
| SaaS 订阅 | 行业协会、园区、企业内控 | 按席位年度订阅，数据隔离托管 |
| 数据服务与定制开发 | 咨询与研究机构 | 专项数据治理、报告模板与算法定制 |

## 9.3 已知局限与改进方向

我们如实披露当前短板并明确改进路径：部分记录正文与日期字段待补全、标签召回率待提升、爬虫健壮性待加强；下一阶段将把自研算法从演示页并入主系统，并增加 SQLite 离线兜底，使巡展环境彻底解除外部依赖。
