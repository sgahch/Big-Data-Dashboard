# 技术方案说明

> 项目：纪检监察大数据看板系统  
> 版本核验时间：2026-09-26（文中数据均为实机查询所得，非文档推断）

---

## 一、系统定位

面向基层监督场景的**数据采集—治理—分析—呈现**一体化平台：自动汇聚各地市公开通报信息，按地区/时间/问题领域三个维度聚合，输出可视化看板与可交付报告。

## 四、核心数据设计

采用显式 `db_table` 固定表名（避免 Django 默认 `app_model` 前缀带来的历史库兼容问题）。

| 模型                       | 表名                         | 说明                                                 |
| ------------------------ | -------------------------- | -------------------------------------------------- |
| `Region`                 | `region`                   | 地市，含域名与路径配置，支持启停与排序                                |
| `TagCategory`            | `tag_category`             | 标签一级分类，带色值                                         |
| `Tag`                    | `tag`                      | 二级标签，携带逗号分隔关键词用于自动匹配，支持 自动/手动 双通道                  |
| `News`                   | `news`                     | 通报文稿主表，含地区外键、冗余地区名、**手动修正标签**与修正理由、修正人             |
| `SupervisionItem`        | `supervision_item`         | 监督事项清单，三层关键词配置（核心词/近义词/上下文行动词）                     |
| `CrawlLog` / `CrawlTask` | `crawl_log` / `crawl_task` | 爬取日志与任务状态机（pending→running→success/failed/stopped） |
| `AuditLog`               | `audit_log`                | 操作审计（新增/修改/删除/爬取/导出/登录）                            |

**设计亮点**：`News` 区分"自动标签"与"手动修正标签"双通道，并留存修正人与修正原因——这解决了纯规则打标必然有误、但纠错过程不可追溯的老问题。

## 六、核心流程

### 6.1 标签自动匹配流程

```
抓取标题 → 取已启用 Tag 的关键词表 → 关键词命中 → 写入 tags(自动标签)
                                            ↓
                    人工复核认为有误 → 写 manual_tags + correction_reason
                                            ↓
                                    is_manual_corrected=True
```

### 6.2 报告导出管线

```
统计聚合（ORM QuerySet） → 组装结构化数据
   ├─ Word   : python-docx  表格 + 段落
   ├─ Excel  : openpyxl    多 Sheet 分维度
   └─ PDF    : xhtml2pdf + reportlab（需注册中文字体）
```

### 6.3 待改进环节（本轮备赛改造点）

1. **正文补抓**：列表页之外跟进正文页，为去重与深度分析提供输入。
2. **日期解析**：部分日期格式未被识别，需扩展解析规则并回填。
3. **打标提升**：把 `SupervisionItem` 三层关键词（核心/近义/上下文行动词）真正接入判定，提高召回。
4. **爬虫健壮性**：处理 404 站点、修复 `category` 字段默认值缺失，加入失败重试与告警。
5. **AI 自研化**：以本地算法替代第三方 API 依赖，保证离线可用（详见 `demos/`）。
6. **离线兜底**：增加 SQLite 分支，解除对 MySQL 的硬依赖，保证巡展环境可一键启动。
