## 二、关键技术决策与原因

| 决策 | 选择 | 为什么（以及代价） |
|---|---|---|
| 后端框架 | Django 4.2 | 自带 Admin 与 ORM，省掉大量后台 CRUD；代价是单体偏重 |
| 数据库 | MySQL 8 | 需要事务与多表关联统计 | 
| MySQL 驱动 | PyMySQL | mysqlclient 在 Windows 上需编译，装不上；PyMySQL 纯 Python，零编译 |
| 定时任务 | APScheduler | 轻量、集成简单；代价是服务重启后调度需重建 |
| 可视化 | ECharts | 中文文档完善、图表类型够用、离线可用 |
| 前端形态 | 服务端模板 + 静态文件直出 | 降低构建复杂度；代价是没有组件化 |
| AI 问答 | 接第三方大模型 API | 快速获得对话能力；**代价是核心智能不在自己手里，且依赖外网**——本次备赛的重点修正项 |

## 三、踩过的坑（如实记录）

1. **依赖装不上**：`python-bidi` 触发 Rust 编译错误，靠锁定版本绕开。
2. **MySQL 驱动编译失败**：Windows 环境 `mysqlclient` 无法编译，切换 PyMySQL 并用 `pymysql.install_as_MySQLdb()` 兼容。
3. **Serverless 跑不了常驻爬虫**：Vercel Function 有执行时长限制，定时任务模型不成立，方案废弃回退到自建服务。
4. **目标站点结构变化导致 404**：部分地区站点改版后爬取失败（详见"已知缺陷"）。
5. **数据库字段缺默认值**：`category` 无默认值导致插入报错，爬取任务失败。

## 四、已知缺陷（不回避，评审可能追问）

| 缺陷 | 实测数据 | 影响 |
|---|---|---|
| 案件正文缺失 | 清风网案件 **100% 无正文** | 依赖正文的去重、深度标签无法生效 |
| 日期解析失败 | **35%** 无日期 | 时间趋势类图表数据不完整 |
| 标签漏标 | **31%** 未打标签 | 违规类型分布不全面 |
| 爬虫成功率低 | 4085 次任务仅 **19 次成功（0.47%）** | 自动化采集链路实际处于亚健康状态 |
| 权限控制未落地 | `DEFAULT_PERMISSION_CLASSES = AllowAny` | 与"多级权限"的宣称不符 |
| 停更 | 最后爬取尝试 2026-05-18，提交止于 2026-03-12 | 数据新鲜度不足 |

> 说明：这些缺陷已在本轮备赛中量化出来，修复计划见《合规评估与改进方案》。**承认缺陷并给出改进路径，远强于被评委现场戳破。**
