## 二、工作量佐证方式

评委核查原创性时，主要看"过程是否可追溯"。建议每人在答辩时能说出：

1. **自己负责模块的一个关键技术难点**，以及当时的解决过程（不是"我用了 Django"，而是"为什么这样建模/踩了什么坑"）。
2. **一次失败与修正**：例如负责爬虫的同学应能讲清 404 站点与字段默认值 bug 的定位过程。
3. **对自己模块的已知不足有清楚认识**：如"目前正文未抓取，这是我们下一步要补的"。

> 能承认不足并说出改进路径，远比背诵功能清单更能拿分。

## 三、协作规范（本轮备赛执行）

| 项 | 要求 |
|---|---|
| 提交粒度 | 每个修复/优化单独一次提交，禁止"大杂烩"一次性提交 |
| 提交信息 | `type(scope): 描述`，如 `fix(crawler): 修复 category 字段默认值缺失` |
| 分支策略 | `main` 保持稳定可演示；开发在 `feature/*` |
| 双盲纪律 | 任何人不得在代码、文档、提交信息、截图、视频中出现院校/导师/单位名 |
| 签署确认 | 全员确认已阅读《双盲合规检查清单》并逐项勾选 |
